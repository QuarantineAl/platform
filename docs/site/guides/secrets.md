Every environment keeps all of its secrets in one file, encrypted with
[SOPS](https://github.com/getsops/sops) and an [age](https://github.com/FiloSottile/age) key:

| | Where |
|---|---|
| Encrypted secrets (in git) | `environments/<env>/secrets.sops.yaml` |
| Private key (on the VM only) | `/opt/quarantine/keys/age-<env>.txt`, mode 0600 |
| Which public key encrypts which file | `.sops.yaml` (`path_regex: environments/<env>/.*`) |
| Plain list of expected keys | `environments/_template/secrets.example.yaml` |
| Decrypted values at runtime | `environments/<env>/.env`, regenerated by `quarantine start`, git-ignored |

The encrypted file is safe in git. The age key is the only way to decrypt it
and has **no recovery**: if it is lost, the environment's secrets are gone.
It never leaves its VM.

:::danger
Never print, copy or paste the contents of `/opt/quarantine/keys/`, of a
decrypted secrets file, or of `.env`. Every authenticated Zitadel user can read
these docs, chats and tickets are not secret stores, and the values are live
production credentials.
:::

## What is in the file

Top-level layout (values omitted):

```yaml
core:
  postgres:      { admin_password }
  zitadel:       { masterkey, admin_password, db_password, provisioner_pat, project_id }
  traefik:       { cloudflare_api_token }
  oauth2_proxy:  { cookie_secret }
  github_runner: { pat }
  ghcr:          { pull_username, pull_token }
apps:
  <app>:         { oidc_client_id, oidc_client_secret, db_password, <generated keys>, ... }
tenants:
  <tenant>:      { credentials_key }          # per-tenant Lazzaretto, prod
machines:
  <username>:    { client_secret }            # quarantine machine add
```

| Source | Keys |
|---|---|
| `quarantine init` generates | Postgres admin password, Zitadel masterkey/admin/DB passwords, oauth2-proxy cookie secret; you supply the Cloudflare token |
| First `quarantine start` captures | `core.zitadel.provisioner_pat` |
| `quarantine start` per app | `apps.<app>.oidc_client_id/secret` (needs_oidc), `apps.<app>.db_password` (needs_db), every `generated_secrets` entry |
| CLI commands | `tenants.<t>.credentials_key` (`tenant add`), `machines.<u>.client_secret` (`machine add`) |
| Set by hand | `core.github_runner.pat`, `core.ghcr.*`, `core.zitadel.project_id`, `apps.kujtime.anthropic_api_key` |

### generated_secrets

An app declares secrets the platform should create for it in `catalog.yaml`:

```yaml title="catalog.yaml (kujtime)"
generated_secrets:
  - key: db_password
    env: DATABASE_PASSWORD_KUJTIME
    generator: alnum32        # 32 random letters/digits
  - key: session_secret
    env: KUJTIME_SESSION_SECRET
    generator: hex32          # 32 random bytes as 64 hex chars
```

On the first `quarantine start` with the app in the manifest, a missing or
`CHANGEME*` value at `apps.<app>.<key>` is generated, written to
`secrets.sops.yaml`, and exported into `.env` as `env`. It is **never
regenerated**, because keys like `LAZZARETTO_CREDENTIALS_KEY` and
`N8N_ENCRYPTION_KEY` encrypt stored data. For Lazzaretto tenants the same
declaration is applied under `tenants.<tenant>`.

## Read one value

On the VM, as root, from the repo. Prefer extracting a single key to dumping
the file:

```bash title="VM"
cd /opt/quarantine/repo
ENV="$(yq '.env' /opt/quarantine/quarantine.yaml)"
SOPS_AGE_KEY_FILE=/opt/quarantine/keys/age-$ENV.txt \
  sops -d --extract '["core"]["zitadel"]["project_id"]' environments/$ENV/secrets.sops.yaml
```

`SOPS_AGE_KEY_FILE` must always be set: sops does not look in
`/opt/quarantine/keys` by itself.

To use a value in a script without it reaching your screen or shell history,
use the CLI's helpers inside a throwaway subshell:

```bash title="VM"
cd /opt/quarantine/repo && bash
source lib/common.sh
PLAIN="$(secrets_decrypt_to_tmpfs /opt/quarantine/repo "$(yq '.env' /opt/quarantine/quarantine.yaml)")"
VALUE="$(secrets_get "$PLAIN" '.apps["kujtime"].session_secret')"
shred -u "$PLAIN"
# ... use "$VALUE" ...
unset VALUE; exit
```

Hyphenated names need bracket syntax: `.apps["delivery-note-ai"].mcp_token`.

## Change a value

Set one key without opening an editor:

```bash title="VM: set the Kujtime Anthropic key"
cd /opt/quarantine/repo
read -rs NEWVAL
SOPS_AGE_KEY_FILE=/opt/quarantine/keys/age-dev.txt sops --config .sops.yaml \
  --set "[\"apps\"][\"kujtime\"][\"anthropic_api_key\"] \"$NEWVAL\"" environments/dev/secrets.sops.yaml
unset NEWVAL
```

(`--config` must come before `--set`.) Or edit interactively in `$EDITOR`,
which decrypts to a temporary file and re-encrypts on save:

```bash title="VM"
SOPS_AGE_KEY_FILE=/opt/quarantine/keys/age-dev.txt sops --config .sops.yaml environments/dev/secrets.sops.yaml
```

Then apply and commit:

```bash
quarantine start          # regenerates .env and recreates containers whose env changed
```

## Committing generated secrets

The VM writes to the tracked `secrets.sops.yaml` (and `manifest.yaml`) whenever
something is generated; the CLI prints
`secrets.sops.yaml was updated — remember to git add/commit/push ...`. Until
that change is on `main`:

- the value exists **only on that VM**, and
- `deploy-platform.yml` refuses to deploy, and `git pull --ff-only` breaks
  once `main` touches the same file.

Get it into git through a pull request:

```bash title="VM: see what changed"
cd /opt/quarantine/repo
git status --short environments/
```

```bash title="Laptop: copy the encrypted file and open a PR"
scp dev-vm:/opt/quarantine/repo/environments/dev/secrets.sops.yaml environments/dev/secrets.sops.yaml
git switch -c chore/dev-generated-secrets
git add environments/dev/secrets.sops.yaml
git commit -m "Commit secrets generated on dev"
git push -u origin HEAD && gh pr create --fill
```

The file you copy is still encrypted. After the PR merges, on the VM:

```bash
git fetch origin && git checkout origin/main -- environments/dev/secrets.sops.yaml
git pull --ff-only
```

Do it in that order. Never `git checkout -- <file>` before the change is on
`main`: that discards the only copy of the generated key.

## Rules

- One age key per environment; dev's key cannot read prod's secrets.
- `verify-secrets-encrypted.yml` fails CI if any `secrets.sops.yaml` is not
  SOPS-encrypted, and `.gitignore` blocks plaintext variants.
- Do not edit a `.sops.yaml` rule's `age` value once secrets exist under it.
- Back up `/opt/quarantine/keys/age-<env>.txt` offline when an environment is
  created; see [Stand up a new environment](/platform/guides/environments/new-environment/).
